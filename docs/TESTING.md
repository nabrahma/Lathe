# Testing

## The levels

| Level | Where | Runtime | Covers |
|---|---|---|---|
| Unit | `internal/*/*_test.go` | < 5 s | Every package, with its edge cases |
| Matrix | `test/matrix` | ~ 10 s | Every task against representative and adversarial input |
| Integrity | `test/integrity` | ~ 4 s | No input file is ever modified, including on a crash |
| Isolation | `test/isolation` | ~ 2 s | Nothing reaches the network during a conversion |
| OCR benchmark | `test/matrix/ocr_test.go` | ~ 12 s | Accuracy regression gate |
| Media | `test/matrix/media_test.go` | ~ 3 s | FFmpeg tasks and real progress reporting |
| Bundle | `frontend/scripts/check-bundle.mjs` | instant | The native-feel and portability rules |

```
make check     # format, vet, import boundaries, tests
go test ./...  # everything
```

Tests that need a component you do not have skip rather than fail, so a
contributor without Tesseract still gets a green run. CI has everything, and so
does the Docker image:

```
docker build -f build/docker/test.Dockerfile -t lathe-test .
docker run --rm -v "$PWD:/src" -w /src lathe-test go test ./...
```

## The golden corpus

`testdata/corpus/`, generated by `scripts/gencorpus` — so it is small,
deterministic, and unambiguously free to redistribute. `make corpus`
regenerates it.

The adversarial set is where the real bugs live, and it is worth listing what
it deliberately contains: a zero-byte file, a truncated PDF, an HTML error page
named `.pdf`, a PNG named `.jpg`, a HEIC header named `.jpg` exactly as a phone
shares it, and filenames containing spaces, quotes, semicolons, command
substitution, backticks, ampersands, non-ASCII text, emoji and 180 characters.

Those filenames are inert only because arguments reach every external tool
through an argv slice and never a shell string. That is the property being
tested; the corpus is how it is tested.

Windows refuses to create filenames containing certain characters that Unix
allows, so the corpus is platform-dependent and `MANIFEST.yaml` says which
entries are Unix-only.

## The three tests that matter most

### Integrity

For every task and every corpus file: hash the input, run the task, assert the
hash and the file mode are unchanged.

Then the part that actually catches things: start a real conversion in a child
process, kill it at a randomised point, and assert the input is still identical
and that no partial file was left at the destination. Eight kills at different
delays, so different pipeline stages get interrupted.

Modifying someone's input file is the one unforgivable bug — they lose a
document and never trust the tool again — so it is enforced structurally rather
than by intention.

### Isolation

Two halves. First, a parse of every Go file in the repository asserting that no
package outside `internal/deps` and `internal/update` imports network code.
Second, the conversion suite run with every outbound name lookup intercepted,
failed and counted; the count must be zero and the conversions must still
succeed.

This is what makes the privacy claim provable rather than promised.

### The conversion matrix

Every task against representative and adversarial input, asserting one of two
acceptable outcomes: a valid output, or a *mapped* error carrying a next action
and no library name, exit code or uppercase shouting. In both cases the input
hash must be unchanged, and a failed job must leave the output folder empty.

`TestEveryLocalTaskIsCoveredByTheMatrix` fails if a task is added without a
case, so coverage cannot quietly rot.

## The OCR benchmark

Character-level accuracy — one minus normalised edit distance — against ground
truth committed beside each corpus image. Results are written to
`docs/evidence/ocr-accuracy.json`, and CI fails on a regression of more than two
percentage points.

**Read the numbers with their caveat.** The corpus is rendered from digital
text and degraded programmatically: skewed a few degrees, vignetted, noised,
blurred and downsampled. That is an easier target than a photograph of
physically printed paper. The benchmark's real value is catching a regression in
the preprocessing chain, not predicting accuracy on a crumpled receipt, and the
README says so.

## Bundle checks

Cheap to write, and each prevents a regression that would otherwise be found
late and by someone else:

- no HTML file input anywhere in the source or the built bundle
- no `<video>` element, which does not reliably fire `ended` on WebKitGTK
- no reference to a font CDN or any other remote host
- no hand cursor on buttons, which is a browser convention
- no `box-shadow`, since elevation is a background step and a hairline
- no `:has()`, container queries, `backdrop-filter` or subgrid, whose support
  varies across the three webviews
- `overscroll-behavior: none` is set

## What is not automated

Usability testing. Five people of mixed technical background, twenty minutes
each, watched without help. Developers find the friction in the CLI and the
power features; everyone else finds it in discovery and naming. Both matter,
they surface different problems, and neither shows up in any test written here.
